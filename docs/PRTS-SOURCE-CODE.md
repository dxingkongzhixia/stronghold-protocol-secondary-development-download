## 1. 目标与非目标

### 目标

- 新增关底 Boss **PRTS，“源代码”** 与对应的 **拟态机械**；
- 同一内容加入**隐藏 Boss**变体；
- 新增 Touch 式策略 **`band_prts_touch`**：每名玩家获得特殊凯尔希 + M3；
- 所有机制以**通用引擎字段**实现，后续插件可复用；
- 默认关闭，不改变原版 Boss 池、默认 golden 与平衡。

### 非目标

- 不做主线兼容层；
- 不新增脚本沙箱或 `trusted` 依赖；
- 不修改原版敌人 / Boss 数据；
- 不做自动更新、不做远程下载。

## 2. 官方依据

| 项 | ID / 来源 | 说明 |
|---|---|---|
| PRTS，“源代码” | `enemy_1564_mpprts` | BOSS，基础 HP 50,000，ATK 1,000，DEF 3,000，RES 75 |
| 拟态机械 | `enemy_1565_mpprme` | BOSS，基础 HP 25,000，ATK 600，DEF 3,000，RES 75，攻击间隔 4 s |
| 官方机制文本 | `enemy_handbook_table.json` | 安全待机 / 危机响应 / 热重启 / 清除协议；拟态的 5 条 |
| 官方战斗数据 | `enemy_database.json`（`levels/enemydata`） | 技能、天赋、黑board、复活上限 |
| Touch 参考 | `band_amedic` / `aceffect_band_61` | `server/sim/content/bands/battle.js` 的 `installMapChars` |

关键官方机制：

- **安全待机**：拟态未倒时 PRTS 不可被攻击；
- **危机响应**：拟态复原期间，PRTS 每受一次伤害，复原时间 -1 s；
- **热重启**：拟态被击倒时，DP 回复速度大幅提高；
- **清除协议**：PRTS 在场上较长时间后，扣除所有目标生命值；
- **拟态重构**：PRTS 未被击败时，拟态每次倒地都会复原，最多 5 次，每次攻击力提升；
- **限制写入**：封锁待部署区费用最高的 4 名干员一段时间；第一次复原后强化；
- **重离子弹性反冲**：光球越飞越弱、溅射越小；
- **动态部署 / 链式反应**：被 PRTS 抓取后悬浮、双目标 / 路径光线。

## 3. 通用引擎能力（先做）

不写死 PRTS。新增以下可被数据配置的 primitives：

### 3.1 Boss 链接与阶段

```json
"link": {
  "enemy": "enemy_1565_mpprme",
  "guard": true
},
"revive": {
  "count": 3,
  "atk": 100,
  "hpReset": true,
  "shortenOnHit": { "target": "boss", "seconds": 1, "min": 3 }
}
```

- `guard`: 链接敌人未倒 → Boss 不可选中；
- `revive`: 链接敌人的复原次数与每次加攻；
- `shortenOnHit`: 打 Boss 缩短链接敌人的复原倒计时。

### 3.2 计时与惩罚

```json
"clearProtocol": { "at": 90, "warning": 10, "lp": 10, "hiddenAt": 75, "hiddenLp": 15 },
"dpRegen": { "multiplier": 3, "duration": 10 },
"deployLock": { "count": 4, "duration": 10, "afterRevive": { "count": 6, "duration": 15 } }
```

### 3.3 弹道 / 悬浮 / 光束

```json
"projectile": { "cooldown": 12, "damage": [2.4, 1.0], "radius": [1.5, 0.45] },
"fly": { "duration": 25, "targets": 2, "range": 3.5, "intervalDelta": -0.5, "hpLoss": 0.3, "knockDownDamage": 0.15 },
"beam": { "interval": 30, "targets": 3, "damageScale": 0.5, "width": 1, "windup": 3, "interruptHp": 0.15 }
```

### 3.4 Band 授予

```json
"grantUnit": {
  "charId": "char_003_kalts", "tier": 3, "elite": true,
  "skill": 2, "skillLocked": true,
  "bonds": ["deputShip", "steadShip", "preciShip"],
  "token": "token_10002_kalts_mon3tr",
  "tokenOnDeath": "downed"
},
"fieldElites": { "count": 2, "pool": "deployed", "random": true },
"restEndBondLayers": { "scope": "self", "layers": 3, "activeOnly": true }
```

引擎按字段执行；数据由插件提供。后续插件可复用同一组字段。

## 5. Boss 设计

### 5.1 数值

| 难度 | `boss_prts` 普通 | `boss_prts_hidden` 隐藏 |
|---|---|---|
| FUNNY | 260,000 | 800,000 |
| NORMAL | 720,000 | 1,100,000 |
| HARD | 1,950,000 | 4,000,000 |
| ABYSS | 3,900,000 | 8,000,000 |
| 轮次 | 14（FUNNY 9） | **15** |
| 权重 | 6 | **50** |
| 拟态复活 | **3 次** | **5 次** |
| 每次复活攻击 | +100 | +150 |
| 护卫 | 拟态 + 2 组精英 | 拟态 + 3 组精英 |

### 5.2 状态机

```
开局：PRTS + 拟态
  ├─ 拟态存活 → PRTS 不可选中
  ├─ 拟态被击倒：
  │    ├─ 全队 DP ×3，持续 10 s
  │    ├─ PRTS 可选中
  │    ├─ 拟态复活倒计时 8 s
  │    │    └─ PRTS 每次受击：倒计时 -1 s（最低 3 s）
  │    └─ 倒计时结束 → 拟态复活（+ATK），次数 -1
  ├─ 拟态复活次数用尽：
  │    └─ 下一次击倒为最终击倒；PRTS 保持可选中直到被击杀
  └─ 清除协议独立计时（见 5.3）
```

### 5.3 清除协议

- 普通：**90 s**；隐藏：**75 s**；
- 最后 **10 s** 红色预警（屏幕边缘 + 顶部提示 + 音效）；
- 到点：每名玩家 **目标生命 -10（普通）/ -15（隐藏）**，只触发一次；
- LP 归零的玩家淘汰，其余继续；
- 不直接清空全队生命——这是对官方“扣除所有目标生命值”的卫戍化改写。

### 5.4 限制写入

- 出场：锁待部署区**费用最高的 4 名**干员，10 s；
- 第一次复活后：锁 **6 名**，15 s；
- 只禁止放入战场，不影响已部署单位。

### 5.5 链式反应（替代弱化节点）

- 第一次复活后解锁；
- 普通每 **30 s**，隐藏每 **24 s**；
- 目标：当前生命最高的 **3 名干员所在格**（隐藏 **5 名**）；
- 从拟态向目标发射 **1 格宽**路径光束，路径上单位受 **0.5× 拟态攻击**（隐藏 0.6×）法术伤害；
- 蓄力 3 s；期间对拟态造成 **15% 最大生命**伤害可打断剩余光束；
- 无可用干员时跳过。

### 5.6 光球 / 悬浮

- 光球：12 s 冷却，最近单位，伤害 2.4→1.0、半径 1.5→0.45 随飞行衰减；
- 悬浮：第一次击倒后进入 25 s 悬浮，2 目标、范围 +2 格、攻击间隔 -0.5 s；受到足量伤害提前落地；
- 隐藏 Boss 的悬浮与光球同样按上表强化。

### 5.7 隐藏 Boss

- 15 轮、隐藏权重 50、血量按 5.1；
- 拟态 **5 次重构**、每次 +150 攻击；
- 清除协议 75 s、-15 LP；
- 链式反应 5 目标、0.6×；
- 限制写入 6 名 / 15 s；
- PRTS 房间触发隐藏 Boss 时，**必然**选择 `boss_prts_hidden`。

## 6. 凯尔希 Touch 式 band

### 6.1 触发

- band：`band_prts_touch`；
- 仅在**房间 Boss 为 PRTS** 时进入策略卡池；
- 任意一名玩家选中后，**全队生效**（参照 Touch 的 team grant）；
- 未选中则不生成凯尔希。

### 6.2 凯尔希

- `char_003_kalts`，**3 本**，**默认非精锐**；
- **固定 3 技能**，不可变更；
- 默认盟约：**助力 `deputShip` + 坚守 `steadShip` + 精准 `preciShip`**；
- 作为场上特殊单位，计入上述盟约的成员；
- 携带可部署的 **M3**：`token_10002_kalts_mon3tr`，**默认非精锐**；
- 凯尔希本身按**持久特殊单位**处理：获得后放在空闲格，可在备战移动，不可出售；被击倒后在下一个备战期回到场上（默认满血）。

### 6.3 精锐门槛（owner 2026-10-20）

- **不额外生成单位**，也**不随机标记**已有干员；
- 凯尔希与 M3 **默认非精锐**；
- 战斗开始时，统计该玩家场上**已部署的、除凯尔希 / M3 之外**的精锐干员数量；
- **≥ 2 名** → 凯尔希与 M3 切换为精锐（属性与状态），本场战斗保持；
- **< 2 名** → 继续保持非精锐；
- **只在战斗开始时检查一次**；战斗中后来凑齐 2 名不再触发。
- 精锐判定排除凯尔希与 M3 自身，避免自己满足自己的条件。

### 6.4 M3

- 套用现有召唤物 / token 逻辑；
- **默认非精锐**；精锐状态随 §6.3 的门槛切换；
- 死亡 → **击倒状态**：留在原格，不攻击、不阻挡、不可选中；
- **击倒状态结束后复活**：默认 20 s，原地满血复活；每场最多 2 次（可配）；
- 具体字段：`tokenOnDeath: "downed"`、`reviveMs: 20000`、`maxRevives: 2`。

### 6.5 休整期 +3

- 每个**休整期回合结束**时；
- 仅**凯尔希自身**；
- 她身上**已激活**的每个盟约 **+3 层**；
- 上限不超过该盟约的 `maxCount`；
- 每回合一次；凯尔希不在场/被击倒时不触发。

## 10. 实现默认与待确认

以下为实现默认；如无异议按此开发：

1. **精锐门槛**：凯尔希 / M3 默认非精锐；**只在战斗开始时检查一次**，若场上已有 ≥2 名**其他**精锐干员，则本场切换为精锐；不额外生成、不随机标记；
2. **M3 复活**：击倒 20 s 后满血复活，每场最多 2 次；
3. **凯尔希**：持久特殊单位，可在备战移动、不可出售；被击倒后下一个备战期满血回归；
4. **+3 上限**：不超过盟约 `maxCount`，每回合一次；
5. **美术**：优先使用本机客户端 PRTS / 拟态 Spine；缺失时回退现有 Boss 模型，并在插件 README 标注。
