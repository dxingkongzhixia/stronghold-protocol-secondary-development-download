# AI 打法与顾问策略（AI-STRATEGY）

> 本文是**示例顾问**（外部 AI / LLM 适配器）的策略说明，也是 `tools/ai/playbook.mjs` 的证据来源之一
> （生成 `sp-playbook/1` 时会对本文取哈希，写进知识包的 `sources`）。
>
> **本文不改变游戏规则**：它只描述“怎么打”。规则以 [`RULES.md`](RULES.md) → [`PLAYING.md`](PLAYING.md) 为准。
> 内置 bot（`legacy`）的行为与本文无关，见 [`BOT-STRATEGIES.md`](BOT-STRATEGIES.md)。
>
> 代码：`server/ai/{playbook,strategy,strategy-community,cycles,knowledge}.js`、
> `tools/ai/{policy,llm-agent,llm-context,llm-plan}.mjs`；接口：[`EXTERNAL-AI.md`](EXTERNAL-AI.md)。

## 1. 证据分层

推荐、估值、角色、阶段界线都是 **[ASSUMED]**（假设性建议），除非明确标注为机制或原话引用。分层如下：

| 层 | 内容 | 来源 | 可验证性 |
|---|---|---|---|
| **机制** | 费用、等级曲线、羁绊阈值、商店规则、敌人数值、Boss 机制 | `data/*.json`（由 `tools/build-data.mjs` 从 `excel/` 生成）、[`DATA.md`](DATA.md)、[`RULES.md`](RULES.md) | 可由代码/数据核对 |
| **规则书** | 玩家可读的完整规则 §1–§7 | [`PLAYING.md`](PLAYING.md) | 随知识包以 `rulesBrief` 发送 |
| **社区证据** | 阵容配方、主/副羁绊、替代件、弱点 | `server/ai/strategy-community.js`（每条带 `source`） | 有出处，但不是官方 |
| **模板建议** | 上述配方的权重、阶段、经济目标 | 本文、`server/ai/strategy.js` | 需实测对比 |

> 知识包里的任何一条都带 `source`，模型被要求“用 ID，不要发明规则”；`rulesBrief` 与之冲突时以规则书为准。

## 2. 顾问的输入

一次决策（`plan` 模式）拿到的是：

1. **公开视图**：回合、阶段、所有人的 LP、等级、羁绊条、已选乐队、本回合敌人预览（组成与路线）；
2. **本座位私有视图**：手牌、备战席、棋盘、商店、资金、道具、可领取奖励；
3. **摘要 `digest`**：经济、羁绊进度、可执行动作（带短 ID）、上回合战斗结果、对手侦察（仅公开信息）；
4. **知识包**：干员/道具/羁绊/乐队/敌人/Boss 的静态目录 + 打法集（`playbook`）+ 规则摘要；
5. **连续性**：上一份计划与被采纳/被拒绝的结果——**观测结果不等于计划已全部执行**。

摘要里不会出现对手的资金、手牌、RNG、种子或其他私有状态。

## 3. 经济

经济是“先活下来、再滚雪球”，不是“越大越好”。本作没有 EXP，只有**商店等级**与**资金**：

- **升级价**随等级上升，且**回合开始时**会比上次升级便宜 1（首回合无折扣，见 `DATA.md` §1）。
- **刷新**只改变商店，**不改变已冻结的槽位**（冻结的是槽位，不是商店整体）。
- **卖出**返还的是该干员的**当前价值**，不是购买价。
- **利息/结转**由乐队机制决定（例如 `band_cannot` 的 `coin_carry_over` 会带来下回合利息），
  不是全局固定利率——知识包里的 `interestDigest` 会按乐队与资金算出“现在/下回合”。
- 备战回合结束时**剩余资金通常清零**（除保留资金的乐队），所以“攒着不用”是有代价的。

**基准（[ASSUMED]，仅作对照，不是硬指标）**：

| 回合 | 目标等级 | 说明 |
|---|---|---|
| R1–R2 | 2 | 先把棋盘铺满，别空位 |
| R3–R4 | 3 | 开始凑第一个羁绊的核心 |
| R5–R6 | 4 | 主羁绊成形；这时才考虑刷新找关键件 |
| R7–R9 | 5 | 需要 5 费核心或高星主 C |
| R10+ | 6 | 只在高血量/高经济时追求 |

> 目标等级是“该回合多数局势下的合理值”；被压制时应提前把钱花在棋盘上，而不是硬升级。

## 4. 阵容

- **一主两副**：一个主羁绊吃满阈值，最多两个副羁绊补足功能（控制、抗线、对空、治疗）。
  同时养三个以上羁绊通常意味着哪个都不满。
- **先看池子**：公共池剩余份数决定能不能凑齐。知识包的 `playbook.bonds[].pairings` 与
  `strategyCandidates` 会给出候选与“缺什么”，但**不保证**池里还有。
- **核心件优先**：主 C 的星级 > 副羁绊的数量。宁可少一个副羁绊，也要让主 C 到二星/三星。
- **对空与抗线**：本作敌人分地面/飞行（`motion: FLY` 与 `canHitFly`），缺对空时后排会被单方面清掉；
  缺抗线时敌人直接绕过前排打主 C。候选里会标 `air` / `block` / `sustain` 能力。
- **过渡不丢核心**：早期拿到的、之后要用的羁绊件不要卖；`keep` 列表就是为此存在的。

## 5. 站位

位置比数值更容易被低估：

- **阻挡位**放在敌人路线上，**输出位**放在不被第一波接触的位置；
- **射程**要覆盖实际路径，而不是“看起来近”；
- 高费主 C 不要放在会被 Boss/远程优先点名的角落；
- 召唤物/装置按技能说明的落点摆放，不要挤占主 C 的射程；
- 顾问的计划只给“建议坐标”，服务器会校验合法性，非法坐标直接拒绝，不会导致对局报错。

## 6. 道具与战术卡

- 道具**只从商店与奖励来**，不能凭空生成；
- 装备有槽位上限（默认每个干员 2 件，第 3 件会替换掉一件——`replaceUid` 指定替换谁）；
- 消耗型道具（`consume_on_equip`）装上即生效，不占槽位；
- 战术卡（机变）按当前棋盘与主羁绊取，别为了一张卡拆掉主羁绊；
- 插件房间可能改规则（例如 `morphPairing: plus` 让变形道具不占槽），以房间的规则选项为准。

## 7. 复盘（连续性）

每回合结束后，摘要里会有**上回合战斗结果**（击杀、漏怪数、Boss 伤害）与 **上一份计划被采纳/拒绝的结果**：

- 计划被拒绝/超时：**保持上一次被接受的方向**（羁绊、买/留/卖、道具、经济偏好），不要每回合换套路；
- 计划被接受但局面没变：可能是资金/池子/槽位不满足，读返回的错误码，不要重复同一动作；
- 观测到的结果不等于计划全部执行：以“实际发生了什么”为准，不以“我想做什么”为准。

## 8. Advisor economy（顾问经济基准）

本节是 `server/ai/playbook.js` 引用 `docs/AI-STRATEGY.md § Advisor economy` 的来源，给出**示例顾问**的
经济偏好基准（[ASSUMED]）：

| 项 | 基准 | 说明 |
|---|---|---|
| `saveForInterest` | 前 6 回合开启 | 有结转机制的乐队才真正产生收益 |
| `reserve` | 0–2 | 只为“下一次刷新就能买”的确定性留钱 |
| `maxRefreshes` | 每回合 ≤ 8 | 超过这个数通常是“找一件不存在的东西” |
| `refreshAbove` | 4 | 手上有 4 金以上才考虑刷新 |
| `level` | §3 的回合目标 | 提前升级只在“差一件就成形”时做 |
| `holdLevel` | 单回合 | 只对本回合有效，不跨回合继承 |

这些数字**不是最优解**，只是让外部模型的计划有一个可对照的起点；用
`tools/botbench.mjs --compare` 对比不同设置的实际结果，再决定是否调整。

## 9. 明确不做的事

- 不发明规则或数值（规则书里没有的，一律不假设）；
- 不读取对手私有信息、不读 RNG/种子；
- 不为“看起来更强”而拆掉已经成形的羁绊；
- 不承诺胜率提升——示例顾问与本文都是工程验证用的基线。
